# Retained number evidence

The original company dashboard now includes **Number checks** for the exact retained input projection returned by `/api/data/{ticker}`. It preserves the existing analysis and financial panels, while distinguishing arithmetic reproduction, exact primary annual input matching, provider assertions, missing definitions and conditional scenario arithmetic. No field receives a blanket verification label.

`retained-number-evidence-v1` independently checks eight calculations: OCF minus absolute PP&E payments; FCF/provider equity market cap; reported interest-bearing debt minus cash; reported interest-bearing debt/equity; and four DuPont components using retained annual flows and ending assets/equity. The debt measure does not mean all liabilities, complete borrowings or a reconciled current balance sheet. DuPont uses ending balances, not verified average balances. Negative earnings remain negative; explicit zero earnings are valid. Missing/nonfinite earnings and nonpositive revenue/assets/equity cannot produce a DuPont model. The current dashboard/API and AI framework section suppress unsupported cached DuPont outputs while preserving the original cache. Fresh DuPont calculations apply the same guard.

Comparisons use Decimal interval arithmetic around retained four-decimal inputs, reported model display precision and float representation intervals. A denominator interval crossing zero is unavailable. There is no arbitrary percentage tolerance for arithmetic agreement. Legacy debt/equity values outside normalized input schema 5 are **definition unverified**, because the cache does not establish percentage versus multiple units or its balance basis. No divide-by-100 migration is inferred. Other source-period or provider-definition differences remain unverified. Old records are retained, not silently corrected.

Primary annual links require the original SEC financial context, exact issuer CIK, USD currency, annual end, concept, accession, filed date, form, unit and value. PP&E signs are compared by magnitude. The separate primary annual ratios remain dated references; they do not verify a provider's trailing, quarterly or average-balance ratio. Missing provenance or a different filing cohort cannot be upgraded merely because numbers look similar. Archived source receipt checks remain the responsibility of `financial_context` and are replayed on captured-report reads.

Quote checks require an explicit timezone-aware timestamp, source, positive finite price and USD currency. Retrieval time never substitutes for quote time. Age is shown, including the 24-hour boundary, but a dated provider quote remains independently unverified. Price × provider shares is compared with reported equity market cap under the existing 25% research tolerance; agreement is only internal reconciliation. No executable quote, share-class reconciliation, current market-cap certification or broker price is inferred.

For supported `equity-scenario-v1` snapshots, a separate Decimal implementation reproduces the ten-year DCF, half-growth fade after year five, terminal growth, current provider share divisor, all nine sensitivity coordinates/prices, and constant-growth reverse DCF when inside its declared search bracket. Base rates/growth retain their full precision; the rounded sensitivity labels are not substituted as calculation operands. Comparison tolerances are disclosed: one cent per share for model prices and 0.05000001 percentage points for rounded reverse growth, plus float representation allowance. This does not validate how growth was chosen, beta, calibrated discount rates, zero future borrowing, future prices, targets or expected returns. Unsupported methods and missing assumptions remain unavailable.

Provider fields and the remaining legacy models are inventoried separately. Source definitions and same-period operands are not retained for a complete independent audit of those values. Their presence is not evidence of correctness. Other model scores, analyst targets and forecasts remain unverified even when one scenario's arithmetic reproduces.

Authenticated API:

- `GET /api/number-evidence/{ticker}` reads the current retained cache and latest available saved financial context without requesting external data.
- `POST /api/number-evidence/{ticker}/capture` accepts only expected input/context SHA-256 values and a 32-character request identifier. A changed cache or source edition returns 409. Repeating the same request is idempotent. No arbitrary numeric inputs or timestamps are accepted.
- `GET /api/number-evidence/reports/{id}` exports exact canonical JSON, its SHA, decoded report and retained inputs only after rechecking original primary context, all report calculations and identifiers. Captures lacking context at creation do not acquire later evidence retrospectively.

Captures live in an immutable `number_evidence_reports` table. Current cache/source snapshots are read consistently; the capture is written atomically. Signed-session and same-origin protections apply. These checks create no funding, fills, portfolio marks, trial observations or real orders. Nonfinite original input markers are retained in evidence while current public numeric values become unknown. Original analyses, caches, saved editions and other evidence tables are not rewritten by this module.

The first audit covered 2,008 retained caches, including 527 original-portfolio symbols. The remaining original symbols lacked retained caches; this is different from the 17 missing historical-price archives. The version-aware audit reproduced 11,106 arithmetic checks, retained 1,035 unverified debt definitions and 3,923 unavailable calculations. All 402 supported scenario snapshots reproduced their declared arithmetic. Independent checks covered 12,080 scalar calculation intervals, 4,422 DCF/sensitivity prices and 402 reverse-growth roots and rounding brackets. These counts establish the stated calculation checks, not full financial verification or investment profitability.
